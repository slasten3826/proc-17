## 0. What This Document Is

This is the long-form chronicle of how proc-17 appeared, what streams entered
it, which failures changed its architecture, what the body can actually do and
why the project is now ready to leave its first laptop.

It is deliberately not:

```text
a session handoff
a release announcement
an executable contract
a replacement for TABLE or CRYSTALL
a claim that every old hypothesis became runtime physics
a claim that proc-17 is complete in every possible sense
```

The old experiment chronicle records individual probes in the shape
`input -> expected -> actual`. This chronicle records the larger causal arc:

```text
where the laws came from
why the first bodies were insufficient
which defects forced each reconstruction
how separate research branches converged into one Lua machine
what survived implementation and falsification
what remains future work rather than hidden unfinished work
```

The next machine should be able to read this document and understand why the
repository has its current shape. It must still use current code, TABLE,
CRYSTALL and MANIFEST as higher authority for exact behavior.

## 1. Evidence Law

This chronicle mixes history, engineering, experiments and myth. They must not
be flattened into one truth class.

| Label | Meaning |
|---|---|
| `RUNTIME_CONFIRMED` | Current code plus a named executable test or grown life confirms the behavior. |
| `REPOSITORY_FACT` | Git, files or current configuration directly confirm the statement. |
| `DOCUMENT_DECISION` | The project selected a direction, but runtime does not prove the general claim. |
| `EXPERIMENTAL_OBSERVATION` | A bounded sample occurred; it does not establish a universal law. |
| `ARCHAEOLOGY` | An older branch contributed pressure or vocabulary but does not govern current code. |
| `MYTH` | A compression of meaning, explicitly not runtime physics. |
| `FUTURE_HYPOTHESIS` | A possible later campaign with no present authority. |

When these conflict, precedence is:

```text
current code plus grown falsifiers
-> current CRYSTALL
-> current TABLE
-> current document decisions and MANIFEST
-> reproducible experiments
-> archaeology
-> analogy or myth
```

Green tests do not make the implementation right by definition. A test may
faithfully prove the wrong contract. A grown counterexample can therefore send
the process back to the earliest lying documentation layer.

## 2. The Whole Story In One Screen

proc-17 began as an attempt to give procesis an executable coding body. It did
not remain a normal coding-agent architecture.

The central inversion became:

```text
ordinary agent:
  model decides -> harness performs -> logs describe

proc-17:
  body owns state, movement, authority, cost, evidence, death and inheritance
  model supplies replaceable semantic current inside bounded organs
```

One Packet is one mortal generation of one task. It is born with the task,
moves through ProcessLang operators, pays budget and identity loss, leaves an
append-only trace and dies terminally. The Packet itself never crosses its
manifest boundary. A lineage may inspect its corpse, build a bounded carrier
and give birth to a clean descendant.

The body now contains:

```text
ten ProcessLang organs
packet mortality and finality
task-shaped field and exact object versions
upper observation plus lower runtime camera
qualified pressure, action plans and opt-in tree authority
L1/L2 vertical life
exact plan delivery
in-memory lineage and NETWORK re-entry
one create-no-replace repository hand
candidate seal finality
one bounded private QA hand
machine CLI
massless authority instrumentation
one complete qualified DISSOLVE treatment and pressure-relief reader
```

The project did not reach this state by implementing one initial blueprint.
It repeatedly found that an apparently complete concept lacked a writer, a
reader, a guard, a truth boundary or a physical witness. Each such failure
forced a more exact body.

## 3. Before proc-17 Had A Repository

The Git history begins on 2026-06-28. The process begins earlier.

### 3.1 Procesis And ProcessLang

Procesis supplied the orientation that a completed form is not merely a static
object. It has a process grammar:

```text
▽ FLOW
☰ CONNECT
☷ DISSOLVE
☴ OBSERVE
☵ ENCODE
☳ CHOOSE
☲ CYCLE
☶ LOGIC
☱ RUNTIME
△ MANIFEST
```

ProcessLang supplied:

```text
a fixed operator alphabet
a canonical adjacency topology
a trace as a walk through that topology
the distinction between language adjacency and runtime direction
the demand that compression, choice and manifestation pay visible costs
```

At first these glyphs could be read as modules, symbols, metaphors or a
language. proc-17 forced the harder question:

```text
What exact fact lets the living body move from one operator to another?
```

That question turned topology into runtime physics.

### 3.2 UPM And The Mathematical Packet

The UPM/MOS packet documents supplied an earlier mathematical body:

```text
Z[K,D] potential/current
raw and formed edges
operator-local state
loss ledger
budget
mode boundaries
NETWORK transport
```

Important consequences survived even though the old packet schema did not:

```text
the Packet is an active process body, not a data bag
relations and form have distinct states
ENCODE changes representation and loses detail
CHOOSE changes possibility and kills alternatives
DISSOLVE changes relations without pretending the underlying material vanished
OBSERVE reads but does not own the observed world
NETWORK is a boundary operation, not ordinary same-life movement
```

The old `Z` was not copied into Lua as one magical scalar or one hash. Its
surviving role was split into a task-shaped potential field, object versions,
derived pressure and explicit evidence. The statement "Z is tension" became a
productive architectural reading, not a literal claim that every current
pressure value is the old tensor.

The old NETWORK design exported a living Packet. proc-17 later rejected that
identity law. What crosses a terminal boundary is bounded evidence and
semantic projection; the living Packet is dead.

Budget and loss were eventually separated because they answer different

Substrate continuity may help, but correctness cannot require an invisible

## 4. How The Project Was Actually Made

The project was not authored by one isolated mind that held a complete design
and translated it into code.

The machinist supplied origin pressure, unexpected connections, rejection of
false "correctness", concrete experiments and the authority to choose a
direction. Multiple machine sessions supplied long-range assembly, contract
exhaustion, implementation, hostile review and reconstruction after context
loss. The repository supplied durable continuity between all of them.

Names such as Codex, Fable, Mythos, Opus, ChatGPT, DeepSeek or later model
labels identify where an observation or implementation pass occurred. They do
not divide ownership into "the human's part" and "the machine's part".

The accurate authorship statement is:

```text
we created conditions in which the parts could be assembled, tested, rejected
and reassembled together
```

This also explains why documentation became structural rather than decorative.
No biological participant needed to keep the full project in working memory.
No machine session was trusted to remember it invisibly. The assembled state
had to live in files.

## 5. The Four-Layer Documentation Machine

proc-17 was itself assembled through the same four-layer process later selected
for its software products:

```text
00_chaos   raw pressure, contradictions, experiments, questions
01_table   entities, states, writers, readers, matrices, falsifiers
02_crystall executable contracts and implementation blueprints
03_manifest measured current result and capability ceiling
```

This stack prevented several kinds of collapse:

```text
an attractive idea could remain a hypothesis
an old path could remain archaeology without silently governing code
an audit finding could survive the session that discovered it
a green implementation could be compared with the contract it was meant to satisfy
a later machine could reconstruct why a strange invariant exists
```

The rule "do not delete, mark as superseded" preserved process history. It also
created a reading cost, so current documents must name source precedence and
new sessions should ingest the active horizon before archaeology.

The complete campaign chain became:

```text
CHAOS
-> TABLE
-> independent cross-audit
-> CRYSTALL
-> red/falsification baseline where applicable
-> implementation
-> focused tests
-> full regression gates
-> MANIFEST/current-state publication
```

This was not bureaucracy added around coding. It was the memory and correction
mechanism that made the body possible.

## 7. The Defect Genealogy

The architecture is easier to understand through the defects that forced it.

### 7.1 Status Without A Guard

Early Packet status fields could be written but did not constrain mutation. A
dead Packet could die again, change its cause, manifest posthumously or accept
new CHAOS.

Fix:

```text
finality guards at every mutating boundary
terminal state is enforced by the body, not caller etiquette
```

### 7.2 Writer Without A Reader

Several fields existed because they sounded useful:

```text
status
grave bequest
compost pattern
rigidity reason
pressure contribution
```

Without a named reader they had no causal role. The project adopted:

```text
every authoritative writer names its reader
an unread record is evidence or residue, not hidden physics
```

### 7.3 Mutable Trace

Append-only trace originally stored payloads by reference. Later mutation could
rewrite an already recorded event.

Fix:

```text
deep-copy at storage boundaries
immutable corpse and carrier snapshots
identity digests over canonical records
```

### 7.4 Eye Treated As A Camera, Camera Treated As An Eye

☱ originally performed a fresh look on each visit and routine budget movement
made it stale almost immediately.

Fix:

```text
continuous immutable runtime frames
bounded reconciliation watermark
no debt when there is nothing to reconcile
```

### 7.5 Double Counting One Fact

`runtime_mismatch` and lower observation debt both read the same stale state,
making ☱ appear twice as strong.

Fix:

```text
one witness per physical fact
absence remains absent
ablation over individual witness sources
```

### 7.6 Constant Witnesses Disguised As Physics

Global revision axes and recurrent relation debt produced route matrices that
looked structured but were mostly constants plus canonical tie-break.

Fix:

```text
per-object id -> version coverage
varying positive and negative matched states
no weight tuning around a missing witness
```

### 7.7 Manifest Laundering

Rejected validation could become a complete manifest because the terminal
assembler read the wrong success surface.

Fix:

```text
rejected remains blocked through output, terminal, death and residue
semantic repair is not claimed when the body has no repair hand
```

### 7.8 Harness Failure Disguised As Body Physics

A missing readiness check in legacy movement could send a Packet to an organ
that correctly returned `nothing_to_reconcile`, then convert this into a harness
error.

Later safety campaigns sharpened the boundary:

```text
ordinary inability or typed effect failure belongs to body physics
trusted implementation contradiction must fail loudly
```

### 7.9 Truth Mixed With Economics

The same corpse changed from unfinished to blocked when lineage money ran out.

Fix:

```text
intrinsic task/completion truth is stable
continuation affordability is a separate lineage decision
```

### 7.10 Generation Mistaken For Stage Identity

Recovery changed `stage_id` because generation number was embedded in its
default identity.

Fix:

```text
one stage identity may span several recovery generations
generation and attempt remain separate coordinates
```

### 7.11 Capability Mistaken For Intention

Model output could propose a path or action, but proposal text is not authority.

Fix:

```text
private grants
exact action envelopes
one-use leases
native containment and read-back
body-owned evidence before completion
```

### 7.12 Semantic Review Mistaken For QA

The roguelike reviewer accepted code that crashed immediately.

Fix:

```text
candidate acceptance requires body-owned runtime QA evidence bound to the exact seal
```

### 7.13 Observer With Mass

An instrument that changes routes is another authority, not an observer.

Fix:

```text
runner-only ledgers
authority and observer epochs
on/off ablation with identical Packet physics
```

### 7.14 Arrival Mistaken For Relief

At coordinate ☷, topology hides the self-targeting DISSOLVE witness before the
effect executes. A naive metric therefore reports relief on arrival.

Fix:

```text
measure the selected pre-effect obligation against an actual post-effect snapshot
require the exact release event
record the successor obligation rather than claiming aggregate disappearance
```

These defects share one family:

```text
the record exists, but the next boundary reads a weaker or different fact than
the writer actually established
```

Most proc-17 progress has been teaching the next reader what the previous
writer really said.

### 8.5 Truth

proc-17 separates:

```text

```

A model response may be stored by a runtime-confirmed event while its content
remains `semantic_proposal`. Transport, hashing and persistence do not promote
semantic truth.

### 8.6 Death And Lineage

Death is final for one Packet. A corpse is immutable. The lineage may continue
only through a new Packet identity.

```text
Packet_n dies
-> corpse
-> intrinsic completion evaluation
-> separate affordability decision
-> bounded carrier
-> NETWORK validation
-> FLOW birth
-> Packet_n+1
```

No live provider handle, capability grant, mutable CALM, field object or local
loss account crosses this boundary.

### 8.7 The First Hand

The repository hand is intentionally tiny:

```text
one explicit physical root
one absent root-level basename
one UTF-8 create-no-replace effect
one independent native read-back
one exact artifact result
```

This is enough to prove capability-safe materialization. It is not enough for
legacy editing or general software development.

### 8.8 The QA Hand

The QA hand can execute one fixed bounded profile against an exact sealed
candidate in an isolated private transaction and return body-owned evidence.

It does not mean:

```text

arbitrary untrusted test commands are safe
the current CLI owns an automatic end-to-end software lineage
```

### 8.9 Instrumentation

Authority instrumentation records evidence outside Packet physics. It is a
measuring instrument, not another organ. Its central proof is masslessness.

## 12. Model Orchestration After The Laptop

The project discovered that most work is not equally reasoning-intensive.

```text
world selection and ontology     rare, expensive
contract exhaustion              sustained, structured
implementation and tests         precise, mostly mechanical
independent audit                cold reconstruction
```

The proposed operational labels are:

```text
Sol   high-context architecture work
Luna  lower-cost bounded execution work
```

These are not proc-17 runtime entities or permanent vendor dependencies.

The intended experiment is:

```text
Sol Ultra  selects a new CHAOS world only when ontology is genuinely open
Sol Max    builds and cross-audits TABLE
Sol High   handles difficult CRYSTALL or security review
Luna High  first performs a read-only reconstruction
Luna       writes bounded CRYSTALL/code/tests if the contract survives
Sol        returns only on an explicit escalation gate
```

The first model switch must occur at a committed artifact boundary. Two models
must not write the same unreviewed campaign concurrently.

The success metric is not whether Luna writes persuasive prose. It is:

```text
same accepted contract
same or stronger falsifiers
green deterministic gates
no authority expansion
materially lower token cost
few or explicit Sol escalations
```

The desktop makes a second comparison possible: cloud Sol/Luna roles versus a
local substrate under the same kernel.

## 15. Final Reading

proc-17 was repeatedly mistaken for the current largest visible result:

```text
a prompt system
a coding agent
a Packet implementation
a ProcessLang runtime
a safe repository writer
a QA sandbox
a lineage engine
```

It contains each of these, but none alone explains the project.

The stable shape is:

```text
proc-17 is the first executable body of procesis:
a kernel in which semantic current may enter, but cannot silently seize
authority over movement, truth, cost, external effects, death or inheritance.
```

The unusual result is not that one person or one model held the entire design.
The result is that the documentation, code, audits and experiments held enough
of one another that the design could keep assembling after no participant could
carry it alone.

The laptop era ends not because every possible feature is built, but because a
coherent body now exists, the accepted DISSOLVE chapter is closed and the
remaining work can be named without pretending the project is still searching
for its center.

The next environment does not inherit a living session.

It inherits a trace.
