## 0. One Sentence

`☷ DISSOLVE` is the bounded sweep phase of a semantic garbage collector:
evidence marks forms that have lost support, and an explicit DISSOLVE tick
releases one exact form while separately accounting for released structure,
irreversible identity loss, and relief of tension.

## 1. The Machinist's Observation

The originating observation was not about software memory:

```text
a concern was once active
attention stopped reinforcing it
time passed
the concern gradually lost its hold
later, its release made room for an insight that was previously unavailable
```

The first naive translation is:

```text
DISSOLVE runs every tick and adds loss every tick
```

The useful part of that sentence is real, but the literal mechanism is unsafe.
It collapses three different physical facts:

```text
age / absence of reinforcement
actual removal of a form
irreversible loss caused by that removal
```

These facts need different owners and different records.

The new hypothesis does not revoke any of those statements. It supplies the

```text

-> bounded evidence that a distinguished L2 form is no longer reinforced
-> derived collection eligibility
```

Therefore the phrase "DISSOLVE works every tick" has two lawful readings:

| Layer | Meaning |
|---|---|
| L1 | The pre-addressable medium cannot remain exactly the same |
| L2 mark | A relevant evidence opportunity can change the derived support status of a form |
| L2 sweep | The operator `☷` explicitly weakens or releases one exact form |

Only the third row is an operator tick. Only the third row can mutate an
addressable relation and charge dissolution loss.

## 3. The Garbage Collector Analogy

The analogy is structural, not decorative.

| Garbage collector | proc-17 hypothesis |
|---|---|
| Object | Versioned field unit, relation, or formed structure |
| Root set | Current task contract, live evidence, selected CALM and other named support sources |
| Reachability | Exact current support through versioned provenance |
| Mark | Pure derivation of supported, unreinforced, contradictory, or unknown status |
| Sweep candidate | Exact form whose lack of support is witnessed rather than assumed |
| Sweep | One bounded `☷` effect |
| Reclaimed memory | Released structural mass returned to potentiality or residue |
| Lost data | Irreversible identity information not preserved in residue |

The analogy has a strict limit: semantic unreachability is not ordinary pointer
unreachability. Absence of a witness is not automatically evidence of absence.
A form may be unobserved because the body did not inspect the relevant domain.
Such a form is `unknown`, not garbage.

## 4. Mark Is Not A Hidden Operator

The mark phase must be a massless derivation from existing immutable evidence.
It must not become a second mutable truth store with an `age = age + 1` counter.

Working shape:

```text
support_age(form)
  = number of relevant completed evidence opportunities
    since the last exact positive support witness

not:
  current body tick - creation tick
```

A relevant evidence opportunity is a completed observation or inspection that:

```text
covered the exact domain in which the form could be supported
named exact object ids and versions
was not truncated, failed, or epistemically unknown
could have produced a positive support witness under the same contract
```

Unrelated body work does not age the form. A budget charge does not age the
form. A failed or partial observation does not age the form. Raw elapsed ticks
are implementation granularity, not semantic time.

The derivation should follow already proven body precedents:

```text
camera: seq + watermark, not "runtime changed somehow"
coverage: object id + version, not global revision equality
probe stamp: exact domain change, not any potential-axis bump
support age: exact support opportunities, not a mutable decay counter
```

The same immutable trace must always derive the same mark state.

## 5. Sweep Is The Operator

Once a qualified witness exists, the ordinary body chain remains mandatory:

```text
exact support/rigidity witness
-> qualified pressure contribution toward ☷
-> exact DISSOLVE action plan
-> readiness consumes the same target and provenance refs
-> router selects ☷
-> destination tick executes
-> field weakens or dissolves the exact form
-> release record and optional residue are appended
-> later readers observe the changed field
```

No background process may silently dissolve field objects. No pressure reader
may mutate them. No router may infer a replacement relation. `☷` releases; it
does not invent what comes next.

The sweep is bounded. One tick does not mean "collect everything". A selected
action names the exact unit or relation, target state, reason, source versions,
and bounds.

## 6. Three Quantities, Not One

The sentence "the collector writes loss equal to the garbage collected" is
close at the level of role, but too compressed for runtime accounting.

The event needs at least three independent quantities:

```lua
{
  released_mass = number,
  irreversible_identity_loss = number,
  pressure_relief = number,
}
```

### 6.1 Released mass

`released_mass` answers:

```text
How much distinguished structure ceased to constrain the active field?
```

It is structural accounting. Its exact unit remains open. It may include a
bounded count or weighted mass of released relations, units and commitments.

### 6.2 Irreversible identity loss

`irreversible_identity_loss` answers:

```text
How much identity information was destroyed rather than preserved or returned?
```

Consequences:

```text
large released mass + complete residue may have zero or low identity loss
small forced release of a still-supported form may have high identity loss
raw relation release has zero formed identity loss
weakening without discard normally has zero identity loss
```

This agrees with the current runtime contract:

```text
preserved residue -> dissolution loss 0
irreversible discard -> explicit fraction in (0, 1]
```

The exact formula is deliberately not selected here. Two candidate families
remain falsifiable:

```text
loss = released_mass * irrecoverable_fraction

loss = released_mass * remaining_live_support * irrecoverable_fraction
```

TABLE must decide what information `remaining_live_support` can honestly mean
before either formula becomes executable.

### 6.3 Pressure relief

`pressure_relief` answers:

```text
How much relevant tension Z disappeared after the form was released?
```

This value cannot be promised by DISSOLVE before execution. It is a comparison
between bounded pressure derivations before and after the field mutation. A
DISSOLVE event can therefore:

```text
reduce Z while increasing loss
```

That is not a contradiction. It is relief at the price of forgetting.

The authoritative field mutation and loss event remain runtime-confirmed. The
claim that the mutation caused later semantic insight remains a proposal until
an ablation demonstrates it.

## 7. What Time Does

Time does not directly dissolve an addressable form.

```text
time / relevant experience
  -> creates opportunities for reinforcement

missed reinforcement
  -> increases derived dissolution pressure

explicit ☷
  -> releases the form
```

In the human analogy, the concern did not disappear because a hidden organ
deleted one piece every second. New experience stopped paying rent to the old
relation. When the relation finally lost enough support, letting it go became
cheap.

The compact law is:

```text
time does not dissolve form;
time deprives unreinforced form of the right to count as fresh
```

## 8. Why Insight Can Follow DISSOLVE

DISSOLVE does not generate insight.

It can only remove a constraint that prevented another lawful process from
forming a different relation:

```text
old rigid relation constrains the field
-> support expires or contradiction accumulates
-> ☷ releases the relation
-> residue/potentiality remains available
-> ☴ observes the changed field
-> ☰ may recognize another relation
-> ☵ may encode a new form
```

Therefore "time produced an insight" is shorthand for:

```text
time weakened the monopoly of an old form;
the body produced the insight after the field was freed
```

This distinction prevents ☷ from becoming a semantic oracle.

What it does not yet provide is the complete new-policy vocabulary:


The semantic-GC hypothesis supplies a candidate meaning for that missing

If confirmed, it closes a lifecycle that is currently open:

```text

-> ☷ weakens/releases it
-> bounded residue returns to potentiality
-> the field can be observed and connected again
```

## 10. Laws The Hypothesis Must Not Break

```text
L01 no field mutation outside an explicit actor-owned effect
L02 no identity loss from marking, observation, elapsed ticks or pressure alone
L03 no support expiry from an unrelated domain event
L04 no "absence" conclusion from failed, truncated or unknown observation
L05 no mutable age ledger beside immutable evidence
L06 no ☷ readiness without exact target/version/reason refs
L07 no replacement relation invented by DISSOLVE
L08 raw release remains distinct from formed identity destruction
L09 preserved residue and irreversible discard remain distinct
L10 body budget, identity loss and tension Z remain separate accounts
L11 a dead Packet cannot be swept or otherwise mutated
L12 collection remains bounded; no unbounded full-field sweep in one tick
L13 every written mark/sweep/accounting record has a named reader
L14 instrumentation failure invalidates evidence; it does not become Packet death
```

## 11. First Falsification Corpus

No implementation is authorized by this list. These are the minimum lives the
later TABLE and CRYSTALL must make precise.

| ID | Matched experiment | Required result |
|---|---|---|
| GC01 | Add unrelated body ticks only | Support age and DISSOLVE pressure remain unchanged |
| GC02 | Exact relevant observation positively reinforces the form | Support age returns to zero or the form is marked supported |
| GC03 | Exact relevant observations repeatedly fail to reinforce the form | Derived age/pressure increases without field mutation or loss |
| GC04 | Relevant observation fails or is truncated | Mark state becomes unknown, not unsupported |
| GC05 | Replay the same immutable evidence | Exact same mark result and witness refs |

| GC08 | Sweep with explicit irreversible discard | Exact positive loss is charged once |
| GC09 | Raw relation is released before formation | Formed identity loss remains zero |
| GC10 | Sweep a stale constraint and rederive pressure | Relevant Z decreases or the hypothesis/target selection fails |

The strongest experiment is a paired life:

```text

B: the same relation loses support through exact relevant evidence

expected:
  only B grows qualified DISSOLVE pressure

  B records released mass separately from loss
  B lowers the exact pressure that selected ☷
```
