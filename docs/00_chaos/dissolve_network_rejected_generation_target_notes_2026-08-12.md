## 14. Transport Alias Found During TABLE Preparation

The first synthesis was still one boundary short.

Current recovery ingress serializes the complete carrier payload into
`chaos.raw_prompt`, and FLOW copies that text into one live `network_carrier`
unit. Creating a second `inherited_rejected_form` unit beside it would not by
itself release the old form:

```text
☷ dissolves the explicit rejected-form unit
but semantic OBSERVE still receives the complete carrier through raw_prompt
therefore the same prior manifest/QA material remains an untyped semantic input
```

That would be a release of one projection while an aliased copy retained the
same practical authority.

The TABLE treatment must therefore split the verified carrier at NETWORK:

```text
transport envelope and full historical payload
  -> lineage/cold evidence; not a semantic field unit

current recovery task projection
  -> live semantic FLOW unit

historical QA evidence projection
  -> bounded evidence/residue; never current child QA

rejected ancestor form applicability
  -> one live direct unit that ☷ may release
```

After release, semantic OBSERVE may receive the current task plus a bounded
historical residue that is explicitly non-authoritative. It must not silently
fall back to the full serialized carrier.

This extends the selected direction; it does not change its owner. NETWORK
still performs verification and projection, FLOW still performs embodiment,
and DISSOLVE still removes only applicability. The new requirement prevents a
second input path from undoing that separation.
