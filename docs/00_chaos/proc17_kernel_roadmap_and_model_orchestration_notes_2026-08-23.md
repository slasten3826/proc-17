## 1. Why The Project Became Hard To Hold

The difficulty is not one enormous algorithm. It is accumulated causal state:

```text
many completed bounded campaigns
many deliberately deferred powers
several generations of superseded documents
runtime evidence at different truth levels
release closure followed by additional internal implementation
similar names for host mechanisms and kernel laws
```

This makes ordinary conversation unreliable as the project index. The
machinist should not have to retain all module and document state in biological
working memory. The documentation stack and roadmap must carry it.

The model also must not repeatedly ingest the whole repository merely to learn
which campaign is active. Repeated cold ingestion is expensive and creates a
second risk: a model can revive superseded directions because it encountered
archaeology without the current disposition.

The cure is not to make every task use maximum reasoning. It is to separate:

```text
world selection      -> rare, high-reasoning CHAOS work
contract exhaustion  -> bounded TABLE and cross-audit work
mechanical precision -> CRYSTALL, code and focused tests
truth publication    -> MANIFEST and release gates
```

Reasoning intensity follows epistemic risk, not file extension or code size.

## 3. Two Different Meanings Of Done

The project needs two explicit finish lines.

### 3.1 Honest v0.1 release

v0.1 is done when the already implemented narrow body is reproducibly
published. It does not require full tree promotion, general DISSOLVE, native
PLAN -> BUILD orchestration, multi-file software or a TUI.

Its purpose is:

```text
prove that proc-17 is an independently executable kernel artifact
freeze one reproducible baseline
stop every future feature from pretending the project has never shipped
```

### 3.2 Full first kernel

The first full proc-17 kernel is done when one body-native software lineage can
lawfully move through the complete necessary tree, create fresh software,
measure it through QA, reject a failed generation, inherit bounded truth and
converge or die honestly.

It does not require:

```text
a proc-17-owned UI
a provider marketplace
legacy repository patching
fine-tuned model weights
a preferred external harness
```

This second finish line is H1-H3. It must not delay the first release.


## 10. Model Work Classes

Model selection follows the cost of a wrong decision.

| Work class | Typical work | Default role | Reasoning level |
|---|---|---|---|
| A0 direction | CHAOS, ontology, authority, threat boundary, finish line | Sol | Ultra |
| A1 contract | TABLE, writer/reader audit, cross-document contradiction | Sol | High or Max |
| A2 independent audit | attack accepted TABLE before implementation | Luna first; Sol on escalation | High |
| M0 crystallization | exact schemas, modules, failures, tests from accepted TABLE | Luna | High |
| M1 implementation | bounded code and focused tests from CRYSTALL | Luna | High, lower if mechanical |
| M2 publication | full gates, MANIFEST, current-state update | Luna or Sol | Medium/High |
| X escalation | new law, authority expansion, repeated unexplained failure | Sol | Ultra |

This table is an operational hypothesis. It must be tested by the Luna pilot.
It does not claim that one model is universally smarter or that code is always
easy.

The intended economy is:

```text
spend maximum reasoning once to choose the correct bounded campaign
spend cheaper sustained attention to execute that campaign
return to maximum reasoning only when the campaign's assumptions fail
```

## 11. Why TABLE And Code Usually Need Less Reasoning

Once CHAOS has correctly fixed:

```text
the entities
authority boundaries
truth statuses
writers and readers
forbidden states
falsifiers
```

TABLE and CRYSTALL work becomes exhaustive rather than mystical. Code becomes
an attempt to satisfy an already explicit contract.

This work is still high-risk when it touches:

```text
native process isolation
capability finality
concurrency or asynchronous effects
cryptographic identity
transaction ordering
cross-generation truth
```

Such work may be mechanically specified but still deserves adversarial review.
Lower cost does not mean lower verification.

## 12. Campaign Artifact Chain

Every nontrivial campaign uses the same chain:

```text
CHAOS
-> TABLE
-> independent cross-audit
-> CRYSTALL
-> red/falsification baseline where applicable
-> implementation
-> focused tests
-> full regression gates
-> MANIFEST/current-state publication
```

No model may skip a layer because it believes the answer is obvious.

Amendment law:

```text
failed implementation against a correct CRYSTALL -> fix implementation
contradictory CRYSTALL -> return to TABLE
contradictory TABLE or new ontology -> return to CHAOS
green tests with false reality -> add falsifier at the earliest lying layer
```

## 15. Escalation Gates

Luna returns the campaign to Sol when any is true:

```text
the TABLE contains a contradiction that changes entity meaning
a required writer or reader does not exist
implementation requires a new truth status or authority
the accepted topology cannot represent the required transition
security depends on an unstated host assumption
the same causal failure survives two bounded implementation attempts
tests and code agree but a grown-life experiment contradicts both
the smallest fix would change another campaign's accepted contract
scope must widen to complete the task
```

Luna does not escalate merely because:

```text
a test is red
a function is long
a schema needs exact validation
the implementation requires several files
formatting or mechanical migration is tedious
one local bug needs reproduction
```

On escalation, preserve the failed evidence. Do not erase it before Sol reads
the causal state.
